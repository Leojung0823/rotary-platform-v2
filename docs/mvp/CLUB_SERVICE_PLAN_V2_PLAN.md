# 年度服務計劃 V2 企劃書

## 1. 目的

「社務」是社員了解本社年度方向與參與成果的入口。社員不只看到一段年度宣言，也能知道四類服務目前做到哪裡、下一步是什麼，以及自己可以怎麼加入。

本功能以扶輪社常見的四類服務為固定架構：

1. 社員服務
2. 職業服務
3. 社區服務
4. 國際服務

資料以 `club_id + Rotary start_year` 隔離。社員只看得到目前社別已發布的資料；草稿與編輯功能只在社務管理模式出現。

## 2. 社員看到的內容

社員從底部或側邊導覽的「社務」進入 `/club-affairs`，看到目前選定扶輪社的年度服務計劃：

- 年度標題
- 年度主軸
- 年度總覽
- 社員參與邀請
- 四類服務的進度
- 每類服務的年度目標、執行活動、最新成果、下一步與社員參與方式
- 最後更新時間

四類服務的說明固定放在產品中，幫助社員快速理解；實際年度目標與成果由幹部填寫。

### 四類服務的內容方向

| 類別 | 內容方向 | 常見例子 |
| --- | --- | --- |
| 社員服務 | 凝聚社員、關懷彼此、培養領導力 | 新會員融入、社員關懷、聯誼、領導培訓 |
| 職業服務 | 以專業互相學習並服務社會 | 職業分享、職業道德、青年職涯、專業志工 |
| 社區服務 | 回應在地需要並和社區夥伴合作 | 弱勢關懷、環境、教育、公益合作 |
| 國際服務 | 促進國際交流、人道援助與和平理解 | 國際交流、全球獎助、人道援助、跨國合作 |

## 3. 社務管理者的編輯流程

管理者從「社務總覽 → 年度服務計劃」進入：

1. 選擇年度服務計劃。
2. 填寫年度標題、年度主軸、年度總覽與社員參與邀請。
3. 分別填寫四類服務的進度、目標、活動、最新成果、下一步與參與方式。
4. 可先儲存草稿；草稿不會出現在社員頁。
5. 四類服務的目標、活動、最新成果與社員參與方式都填妥後，才可發布。
6. 已發布資料仍可在管理模式編輯；再次儲存會保留第一次發布時間並更新最後修改時間。

管理畫面只使用固定的 `clubId` 路徑與後端 RPC。頁面連結不是權限邊界，直接輸入管理網址仍會由後端拒絕沒有權限的人。

## 4. 權限與資料安全

- `service_plan.manage` 授予平台管理員、社長、秘書；既有受控的社級管理員也保留管理能力。
- `member.read` 是社員讀取社務資料的必要條件。
- 成員模式一律以 `p_as_member = true` 讀取，管理者切換到成員模式時也不能看到草稿或編輯入口。
- 管理模式明確以 `p_as_member = false` 讀取，後端再次檢查 `service_plan.manage`。
- 服務計劃與四類內容的資料表不授予瀏覽器角色直接讀寫權限。
- 所有寫入都經過 security definer RPC，並記錄稽核事件。
- 所有查詢都帶入 `club_id` 與年度，不能跨社或跨年度共用資料。

## 5. 資料生命週期

- 每個扶輪社每個 Rotary 年度只有一份計劃。
- 舊版只有標題與年度總覽的資料仍可讀取；四類欄位沒有資料時顯示「尚未補充」，不會捏造成果。
- 草稿發布後社員才可見。
- 取消發布會回到草稿，社員不再看得到；歷史更新與第一次發布時間留在同一筆計劃資料。
- 每次 V2 儲存記錄操作者、社別、年度、狀態與四類資料筆數。

## 6. 驗收條件

- 一般社員從「社務」可看到四個分類，且只能看到目前社別已發布的年度內容。
- 管理者在社員模式看到的頁面與一般社員相同，不會出現編輯、草稿或管理連結。
- 社長、秘書與受控社級管理員可在管理模式看到「年度服務計劃」工具卡。
- 無 `service_plan.manage` 的社員手動進入管理網址時，後端拒絕，不只是前端隱藏連結。
- 草稿儲存成功但社員頁不顯示；發布時四類的必要欄位未完成會被拒絕。
- 同一社別與年度重複儲存會更新原資料，不會產生第二份計劃。
- 外社社員、停權帳號、匿名訪客不能讀取或修改本社服務計劃。
- migration、RPC、資料表與管理頁都有對應的安全邊界測試。
