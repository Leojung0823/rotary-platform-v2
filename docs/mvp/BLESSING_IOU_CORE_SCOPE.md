# 祝福 IOU 核心範圍

本文件定義「祝福牆與捐款承諾核心」這一個可獨立上線的完整領域。收款與年度統計分開開發、分開審查，避免一個 PR 同時改動過多財務規則。

## 這一版包含

- 有效社員可以在自己的扶輪社寫一般性祝福，不必指定社員或活動。
- 祝福文字供同一扶輪社的有效社員查看，跨社資料必須拒絕。
- 社員可以不填金額，只送出祝福。
- 幹部可以決定該社是否允許社員公開金額。
- 即使社內允許公開，每筆新祝福仍由社員自行選擇隱藏金額，畫面預設為隱藏。
- 開啟社內公開設定時，舊資料不會自動改成公開。
- 社員可以修改或軟刪除自己的資料；授權幹部可以填原因後軟刪除。
- 祝福與個人金額 API 一律使用 `no-store`，不做跨使用者快取。
- 功能由 `blessing_iou_v1` 控制，`DISABLE_BLESSING_IOU=true` 可以立即關閉入口。

## 權限與隔離

- 瀏覽器不能直接讀寫 `blessing_iou_entries` 或 `club_blessing_iou_settings`。
- 所有操作都經過固定 `search_path` 的 server-authoritative RPC。
- 社員權限以目前登入者、有效社籍與 `club_id` 一起判斷。
- 幹部權限使用獨立的 `blessing_iou.manage`，不把平台管理員自動當成社內財務幹部。
- 公開祝福牆不顯示收款狀態。
- 稽核紀錄只保存操作類型、是否有承諾與公開狀態，不複製祝福文字或金額。

## 首頁效能界線

登入後首頁只顯示一張靜態入口卡，不查詢祝福或金額。使用者進入祝福牆後才載入該社資料，等待期間先顯示骨架畫面。

## 分開處理的後續領域

1. 收款與沖銷：單筆、批次、部分收款、不可變更的調整紀錄；收到任何款項後鎖定社員修改與取消。
2. 扶輪年度報表：每月應收、已收、未收與社員統計；年度固定為 7 月 1 日到隔年 6 月 30 日。

在收款領域完成前，管理畫面不得把目前資料誤稱為「已收款」。
