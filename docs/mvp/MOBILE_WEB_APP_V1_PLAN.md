# 「我是扶輪人」PWA 升級企劃書（修訂版）

更新日期：2026-10-01（Asia/Taipei）
提案：@鍾昀哲

## 一、專案背景

本次升級不重做系統，而是把現有「我是扶輪人」Web App 升級為可安裝的網頁應用，讓社友可以把它放到手機桌面，一點就開。

目前「我是扶輪人」已可透過網址使用，但社友每次都要從 LINE、瀏覽器或書籤找到網址再開啟，感受仍像「網站」而非手機 App。完成後，社友可從手機桌面點擊「我是扶輪人」圖示，以獨立視窗開啟系統，不必先找瀏覽器或記網址。

社友主要透過 LINE 接收連結，而 LINE 內建瀏覽器無法完成一般的加入主畫面安裝流程。因此，「如何從 LINE 順利導到可安裝的瀏覽器」是核心工作，不是附帶細節。若入口改用 LIFF URL，須另行驗證導流方式；LINE 的 `openExternalBrowser=1` 參數不適用於 LIFF URL。

## 二、專案目標

核心目標：讓不熟悉手機操作的社友，從 LINE 收到連結開始，用最少步驟把「我是扶輪人」加入手機桌面，並在桌面 Web App 中正常登入使用。

平台目標流程：

- 共同第一步（LINE）：社友在 LINE 點擊一般 Web URL 後，系統嘗試以手機外部瀏覽器開啟；若仍停留在內建瀏覽器，頁面提供清楚的外開教學。若目前入口是 LIFF URL，須另外確認導流方案，不假設外開參數有效。
- Android：開啟頁面 → 按「安裝到手機」→ 若瀏覽器支援，顯示系統安裝確認 → 按「安裝」→ 桌面出現圖示。若無法一鍵安裝，改顯示「⋮ → 加到主畫面／安裝應用程式」教學。
- iPhone：開啟頁面 → 按「安裝到手機」→ 顯示「分享 → 加入主畫面 → 加入」教學 → 桌面出現圖示。網站不能代替使用者完成加入主畫面操作。
- 安裝後第一次開啟：從桌面圖示開啟，在該 Web App 環境完成一次 LINE Login；確認該環境中的登入狀態有效後，往後於 Session 有效期間維持登入。

整個過程以「社友不需要詢問任何人」為設計與驗收標準。

## 三、設計原則

原則是最小幅度修改現有系統，最大幅度改善手機使用體驗。

| 項目 | 原則 | 備註 |
| --- | --- | --- |
| 現有網站功能 | 保留 | 原網址繼續可用；未安裝者照常使用 |
| 後端資料庫／Supabase | 不修改 | 不新增資料表或改動既有資料流程；Service Worker 不快取 Supabase 請求 |
| 登入系統／LINE Login | 原則不更動 | 若 iPhone 桌面模式登入回跳異常，先用實機查明原因，再限縮調整回跳網址與流程 |
| UI | 僅新增安裝入口、教學提示及更新提示 | 不重做既有系統介面 |
| 上架 | 不需上架 App Store／Google Play | 透過 HTTPS 網站安裝至主畫面 |
| 版本更新 | 偵測到新版本後提示使用者 | 使用者點擊更新後切換至新版；不承諾未互動即自動切換 |
| 執行環境 | 全站 HTTPS | PWA 安裝的必要條件 |

安全與相容原則：

1. Service Worker 只處理同源 `GET` 請求；登入頁、登入後 HTML、Supabase API、LINE Login 與其他即時資料請求不得進入 Cache Storage。
2. 僅快取明確列入 allow-list 的公開靜態資源（例如圖示、字型、必要的版本化靜態檔）及不含個人資料的離線提示頁；導覽採網路優先，離線時不得顯示舊的登入後畫面。
3. Service Worker 註冊或更新失敗不得阻擋登入或首頁使用；Service Worker 腳本使用適當的重新驗證快取標頭，避免長期套用舊快取規則。
4. 新版偵測應符合 Service Worker 的安裝、等待與啟用生命週期：偵測到新版後提示使用者；使用者點擊更新後才切換並載入新版。另需比對目前頁面的 Next build ID 與不快取的 `/api/app-version` 回應，避免只在 `sw.js` 改變時才偵測到發布；此端點只回傳 build ID，不讀取認證資料或連線 Supabase。
5. 固定網址的公開資源（圖示、Manifest 等）採網路優先、離線時使用已快取副本；Next 內容雜湊靜態資源可快取優先，避免固定 URL 的新版圖示或 Manifest 永久停留在舊快取。
5. 開發與測試階段不修改資料庫、Supabase 權限或正式環境設定。正式發布須另依發布流程核准。

## 四、使用者最終體驗

安裝完成後，社友手機桌面會出現名稱為「我是扶輪人」、搭配正式圖示的入口，點開後以獨立視窗執行，不顯示一般瀏覽器網址列。

- 圖示清晰，Android 不會出現異常白邊或被裁切。
- 開啟時顯示品牌色背景與圖示，不出現明顯白屏。
- 第一次從桌面 Web App 開啟時，若該環境沒有可用 Session，提示使用 LINE Login；登入後在該環境維持有效 Session。
- 網站偵測到新版後顯示更新提示；社友點擊後切換至新版。不得承諾每次下次開啟必然已自動更新。

社友的感覺是「我在打開一個 App」，而不是「我在進入一個網站」。

## 五、主要風險與對策

前兩項會直接影響驗收，須在介面開發前優先處理並以真機驗證。

| 優先 | 風險 | 影響 | 對策 |
| --- | --- | --- | --- |
| 高 | LINE 內建瀏覽器無法安裝一般 Web App | 社友從 LINE 點連結後，Android 不出現安裝提示、iPhone 沒有「加入主畫面」，流程第一步失效 | 一般 Web URL 對外分享時附加 `openExternalBrowser=1`（已有 query string 時合併參數）；網頁另偵測 LINE、Facebook 等常見內建瀏覽器並提供「點右上角 ⋯ → 用瀏覽器開啟」教學。LIFF URL 不支援此參數；若使用 LIFF URL，須另行驗證導流方式。 |
| 高 | iPhone 桌面 Web App 與 Safari 的登入儲存環境可能不同；LINE Login 回跳可能落在 Safari | 社友安裝後可能須重新登入；若登入成功卻回到 Safari，桌面 Web App 仍可能未登入 | 安裝教學預告首次從桌面開啟可能需要登入。程式盤點顯示目前 Supabase SSR browser/server client 透過 Cookie 儲存 Session（`src/lib/supabase/client.ts`、`server.ts`）；仍須在 iPhone 桌面 Web App 中實機驗證 LINE Login、回跳及 Cookie/Session 保存；若異常，只調整必要的回跳設定與流程。Safari 已登入不等於桌面 Web App 一定已登入。 |
| 中 | Service Worker 快取不當 | 社友卡在舊版畫面、登入狀態錯亂或看到過期資料 | 第一版採保守策略：導覽網路優先；Supabase、登入及即時資料請求一律不快取；只快取核准的公開靜態資源與離線提示頁。偵測到新版後提供更新提示。 |
| 中 | Android 一鍵安裝事件不一定出現 | 部分瀏覽器或特定狀況下，按鈕無法叫出安裝確認 | 一鍵安裝不可用時，按鈕仍顯示可完成的「⋮ → 加到主畫面／安裝應用程式」圖文教學，不可按下後沒有回應。 |
| 低 | 圖示與啟動畫面品質不佳 | 圖示模糊、Android 白邊或 iPhone 開啟白屏，降低「像 App」的感受 | 提供一般與 maskable 圖示及 180×180 Apple Touch Icon，設定啟動畫面背景色，並以實機檢查裁切與清晰度。 |

## 六、具體執行步驟

共 14 步，分為四個階段；LINE 導流與桌面登入驗證排在安裝介面開發之前，先排除最大風險。

### 第 1 階段：盤點與基礎建置

1. 確認目前網站架構：前端框架、部署平台、是否已有 Manifest 或 Service Worker、LINE Login 回跳網址設定及全站 HTTPS 狀態；盤點 Supabase Auth Session 的實際儲存方式。
2. 建立 Web App Manifest：設定 `name` 與 `short_name` 為「我是扶輪人」，以及穩定的 `id`、`start_url`、`scope`、`display: standalone`、主題色與背景色。明確設定 `id` 與 `scope`，並依實際正式網址確認其值。
3. 製作正式 App Icon：192×192、512×512、512×512 maskable 版本（Android 裁切用，圖案置中並留安全邊距），以及 180×180 Apple Touch Icon。
4. 加入 Service Worker：採保守快取策略（見第三節）；加入新版偵測與「點此更新」提示。離線導覽只顯示不含個人資料的離線提示，不回傳舊的登入後 HTML。

### 第 2 階段：先驗證高風險項目

5. LINE 外開處理：一般 Web URL 對外分享時附加 `openExternalBrowser=1`；若網址已有 query string，正確合併參數。偵測內建瀏覽器並顯示「用瀏覽器開啟」教學。若入口使用 LIFF URL，不套用此外開參數，先確認可行的替代導流方式。
6. 桌面模式登入驗證：在 iPhone 與 Android 真機上，從桌面圖示開啟並完成 LINE Login，確認回跳目的地、登入狀態及重開後 Session；如有問題，在此階段調整必要的回跳流程。

### 第 3 階段：安裝介面

7. 新增「安裝到手機」入口，使用第七節文案，不對一般社友顯示「PWA」字樣。
8. Android 安裝流程：可一鍵安裝時叫出系統安裝確認；不可用時改顯示「⋮ → 加到主畫面／安裝應用程式」圖文教學。
9. iPhone 安裝流程：偵測 iPhone；按下按鈕後顯示「分享 → 加入主畫面 → 加入」極簡教學，並預告首次從桌面開啟時可能需要登入一次。
10. 偵測已安裝狀態：從桌面獨立視窗模式開啟時，不顯示首頁安裝卡片或安裝教學。
11. 建立安裝教學頁 `/install`，作為 LINE 群組與 QR Code 的固定入口。一般 Web URL 預設附加 `openExternalBrowser=1`；如入口採 LIFF URL，須另行驗證導流方式。

### 第 4 階段：測試與發布

12. 依第八節測試清單逐項執行，並記錄裝置、作業系統、瀏覽器、結果與未通過項目。
13. 執行功能回歸測試：登入、LINE Login、Supabase 讀寫、頁面跳轉、返回、登出再登入、手機休眠後恢復及新版更新流程。
14. 通過測試與使用者驗收後，依正式發布流程部署，製作指向 `/install` 的 QR Code，先邀請 2–3 位社友試用，再決定是否全面推廣。正式發布和正式環境設定變更須依既有核准流程辦理。

## 七、安裝入口設計與文案

所有對社友的文字都不出現「PWA」，只講「安裝到手機」與「加入桌面」。

### 主要安裝卡片

- 標題：📲 安裝「我是扶輪人」
- 說明：加入手機桌面，下次一點就開。
- 按鈕：安裝到手機

### 不同情境下的提示文字

| 情境 | 顯示內容 |
| --- | --- |
| 在 LINE 等內建瀏覽器中 | 請點右上角「⋯」，選擇「用瀏覽器開啟」，即可安裝到手機。（附圖解） |
| iPhone 按下安裝 | 只要三步：① 點下方「分享」按鈕 ② 選「加入主畫面」③ 點右上角「加入」。（附圖解或動畫） |
| Android 無法一鍵安裝 | 請點右上角「⋮」，選擇「加到主畫面」或「安裝應用程式」。（附圖解） |
| 安裝後第一次開啟 | 歡迎使用！如果尚未登入，請用 LINE 登入；登入後在這個桌面 App 中繼續使用。 |
| 偵測到有新版本 | 「我是扶輪人」有新版本，點此更新。 |

一般 Web URL 對外分享時附加 `openExternalBrowser=1`；若 URL 已含其他 query string，須合併參數，不可覆蓋原參數。LIFF URL 是例外，不能假設加上該參數就會外開。

### 顯示位置與頻率

- 首頁上方顯示安裝卡片；社友可點「稍後再說」關閉，關閉後 7 天內不再主動顯示。
- 選單中保留固定的「安裝到手機」入口，隨時可找到。
- 已從桌面獨立視窗開啟時，不顯示安裝卡片或安裝教學。
- 偵測到 Service Worker 新版時顯示更新提示；使用者點擊後切換到新版，不以未互動狀態承諾自動更新。

## 八、驗收測試清單

本專案以「一般社友不需詢問工作人員，即可自行完成安裝並正常使用」作為最終驗收標準。

### 1. LINE 導流測試

| 測試項目 | 驗收標準 |
| --- | --- |
| Android 從 LINE 點擊一般 Web 安裝連結 | 可順利導向外部瀏覽器；若未成功外開，頁面立即顯示「用瀏覽器開啟」圖文教學 |
| iPhone 從 LINE 點擊一般 Web 安裝連結 | 可順利導向可執行「加入主畫面」的瀏覽器環境；若仍停留於 LINE 內建瀏覽器，顯示清楚的外開教學 |
| LINE OA Rich Menu 與活動通知連結 | 一般網站 URI 均可導向外部瀏覽器，且保留原本活動或社別路徑與參數；此項須以 iPhone、Android 的 LINE App 實測 |
| LIFF URL 入口（如有） | 不假設 `openExternalBrowser=1` 有效；須先確認並記錄實際可用的導流流程 |
| 內建瀏覽器偵測 | LINE、Facebook 等常見內建瀏覽器可被正確辨識 |
| 操作說明 | 使用者不需詢問管理員，即可知道下一步如何操作 |

### 2. Android 安裝測試

| 測試項目 | 驗收標準 |
| --- | --- |
| 支援一鍵安裝的瀏覽器 | 點擊「安裝到手機」後出現系統安裝確認 |
| 不支援一鍵安裝的瀏覽器 | 顯示「⋮ → 加到主畫面／安裝應用程式」教學 |
| 安裝完成 | 手機桌面出現「我是扶輪人」正式圖示 |
| App 開啟模式 | 從桌面圖示開啟後以獨立視窗執行，不顯示一般瀏覽器網址列 |
| 已安裝狀態 | 從桌面 App 開啟後，不再顯示任何安裝提示 |

### 3. iPhone 安裝測試

| 測試項目 | 驗收標準 |
| --- | --- |
| 點擊「安裝到手機」 | 顯示「分享 → 加入主畫面 → 加入」三步驟教學 |
| 加入主畫面 | 桌面正確出現「我是扶輪人」圖示 |
| App 開啟模式 | 從桌面開啟後以獨立 Web App 模式執行 |
| 首次登入提示 | 第一次從桌面 Web App 開啟時，清楚提示若尚未登入，需使用 LINE 登入一次 |
| 已安裝狀態 | 桌面 Web App 中不再出現安裝卡片及安裝教學 |

### 4. LINE Login 與登入狀態測試

此項目列為本專案最高優先驗收項目之一。Safari 中的登入狀態不能直接當作桌面 Web App 已登入的證據；驗收須在已安裝的桌面 Web App 環境中實際登入及確認 Session。

| 測試項目 | 驗收標準 |
| --- | --- |
| Android 桌面 Web App LINE Login | 可完成登入並正常返回「我是扶輪人」 |
| iPhone 桌面 Web App LINE Login | 可完成登入，且登入完成後可繼續在桌面 Web App 中使用 |
| LINE Login 回跳 | 不得出現登入成功但桌面 Web App 仍停留於未登入狀態的情況 |
| 關閉後重新開啟 | 在 Session 有效期間內，登入狀態仍可正常維持 |
| 手機重新啟動後使用 | 在 Session 有效期間內，不需重新登入 |
| 登出 | 登出後該 Web App Session 正確清除 |
| 再次登入 | 登出後可再次正常使用 LINE Login |

若 iPhone 桌面模式 LINE Login 發生回跳至 Safari、Session 無法在桌面 Web App 中使用或其他異常，須在正式發布前完成登入流程或 Redirect URL 調整並重新驗收。亦須依目前 Supabase Auth 實際使用的儲存方式判定 Safari 與桌面 Web App 的 Session 是否可共享，不可只依 Safari 已登入推論。

### 5. 系統功能回歸測試

PWA 升級不得影響原有「我是扶輪人」功能。須確認：

- 原網址仍可直接透過瀏覽器正常使用。
- Supabase 資料讀取正常。
- Supabase 資料新增、修改及刪除功能正常。
- 頁面跳轉及返回上一頁正常。
- LINE Login、登出及重新登入正常。
- 手機休眠後重新開啟系統正常。
- 網路暫時中斷再恢復後，系統可重新取得資料。
- Service Worker 不快取登入、Supabase API、Cookie、個人資料或其他即時資料請求。
- 離線導覽只顯示不含個人資料的安全提示，不顯示快取的登入後畫面。

### 6. 版本更新測試

| 測試項目 | 驗收標準 |
| --- | --- |
| 發布新版本 | 已安裝舊版的手機可偵測到新版 |
| 更新提示 | 顯示「我是扶輪人有新版本，點此更新」 |
| 使用者點擊更新 | 系統啟用新版並切換／重新載入至新版 |
| 更新後資料與登入狀態 | 前端更新不應清除帳號資料或造成正常 Session 異常遺失 |
| 舊版快取 | 不得長期停留在已失效的舊版介面；未點擊更新時不得宣稱已完成切換 |

### 7. 視覺與使用體驗測試

正式發布前須確認：

- 圖示須使用本產品所代表之扶輪社／地區／正式扶輪實體核准的識別素材。Repository 目前沒有該正式識別圖檔；目前由既有通用 R 圖示產生的 PNG 只作為開發占位，正式發布前須替換為核准素材或取得明確確認。依[扶輪官方品牌中心標誌規範](https://brandcenter.rotary.org/en-us/our-brand/brand-elements/logos-and-graphics/rotary-logos)，宣傳特定扶輪實體時應使用其客製化標誌，不可只以 Rotary Masterbrand Signature 代替；不得自行把扶輪齒輪單獨當成正式品牌圖示。
- Android 圖示沒有異常白邊或裁切。
- iPhone 主畫面圖示清晰。
- App 名稱正確顯示為「我是扶輪人」。
- 開啟時使用品牌背景色，不出現明顯白屏。
- 安裝說明不得出現「PWA」等一般社友不熟悉的技術名詞。
- 首頁安裝卡片可選擇「稍後再說」。
- 選擇「稍後再說」後，7 天內不再主動顯示。
- 選單中始終保留「安裝到手機」入口。
- 已安裝並從桌面啟動時，不再顯示安裝相關介面。

### 8. 最終使用者驗收

正式全面推廣前，至少邀請 2–3 位非開發人員、且手機操作熟悉度不同的扶輪社友進行實際測試。測試人員只提供一則 LINE 訊息與安裝連結，不另外口頭指導。

完整流程應能自行完成：

**LINE 收到連結 → 開啟正確瀏覽器 → 安裝到手機 → 找到桌面圖示 → 開啟「我是扶輪人」→ LINE 登入 → 正常進入系統**

若測試者在過程中必須詢問「下一步要按哪裡」，即視為該步驟的介面或教學仍需調整，完成調整後重新測試。

### 最終驗收標準

本專案完成的判斷，不以「網站具備可安裝網頁應用技術」為標準，而以：

**「社友收到 LINE 連結後，可以自己把『我是扶輪人』加入手機桌面，之後直接從桌面打開並正常使用。」**
