# 介面設計企劃書：從「能用」到「看起來被認真對待」

建立日期：2026-09-14（Asia/Taipei）

範圍：56 個頁面、23 份樣式檔、`src/app/globals.css`（341 行）為設計系統核心。

本文件不是風格提案，是**一份有證據的檢討與一套可執行的規則**。設計決定都附上它解決的具體問題。

## 1. 先講最重要的發現

**這個專案的介面違反了它自己寫的無障礙標準。**

`UX_SENIOR_FRIENDLY_AUDIT_PLAN.md` §4.1 明定：

> 正文至少 16px；輔助文字不低於 14px。10–12px 只可用於不影響理解的品牌小字，不可用於主要狀態或操作。

實際狀況：

| 字級 | 宣告次數 |
|---|---|
| 13px | 23 |
| 12px | 17 |
| 11px | 10 |

而 `.subtle` 與 `.hint`（兩者都是 13px）在元件中被使用 **55 次**，承載的是「填了之後社員到現場可以直接用手機定位簽到」這類**真正要讀的說明文字**，不是品牌小字。

這不是美感問題，是**規範沒有被落實到設計系統裡**。只要 token 允許 13px，每個人都會用 13px。

## 2. 為什麼現在看起來不高級

以下每一條都指向具體的程式碼，不是主觀感受。

### 2.1 所有東西都在強調，於是沒有東西被強調

現行字重同時存在 **850、800、760、700、650**：

- `.eyebrow`：12px + `font-weight: 850` + `text-transform: uppercase` + `letter-spacing: .18em`
- `.button`：`font-weight: 800`
- `.metric-label`：`font-weight: 700`
- h1：`font-size: clamp(30px, 4vw, 46px)`

當標籤、按鈕、數字、標題全都用最重的字重喊話，畫面就只剩噪音。高級感來自**克制**——讓少數元素承擔強調，其餘退後。

### 2.2 邊框與陰影同時存在

`.card` 是 `1px 邊框` ＋ `0 10px 30px rgba(18,48,74,.08)` 的大範圍陰影。兩者都在做「把卡片抬起來」這件事，同時用就顯得用力。

而且**全站只有一個陰影值**，意思是所有東西的「高度」都一樣——沒有真正的層次，只有一層統一的浮起。

### 2.3 CJK 標題用了負字距

```css
h1 { letter-spacing: -.035em; }
```

負字距是拉丁文 display 字體的手法。**中文字本身已經是等寬方塊，負字距會讓筆畫互相擠壓**，在 40px 以上特別明顯。這同時是美感與可讀性問題。

### 2.4 Eyebrow 被過度使用

幾乎每張卡片與每個頁首都有一行大寫寬字距的小標。原意應該是點綴，但在這個密度下它變成每個區塊都要先讀一行噪音，而且**每處都吃掉一行高度**。

### 2.5 間距沒有尺度

現行值包含 30、28、24、22、20、18、16、14、12、10、8、6、4 px，看得出是逐元件挑的。沒有尺度，畫面的節奏就是隨機的——這是「業餘感」最常見的來源，比顏色更致命。

### 2.6 金色幾乎沒被使用

扶輪的識別是**深藍＋金**。但 `--gold` 目前只出現在品牌圓標與頭像底色，其餘強調色一律用 `--blue: #1677a8`——一個沒有來歷的通用藍。

## 3. 設計方向：什麼是「全年齡向的高級感」

必須先否定一個常見的誤解。**對這個使用者群（多為中高齡專業人士），高級感不是**：

- 更細的字重
- 更低的對比
- 更小的字
- 極簡到資訊不足

**而是**：

- **留白充足**——讓內容有呼吸，而不是塞滿
- **克制的色彩**——少數顏色，用得準
- **明確但不喧鬧的層級**——大小與間距決定重要性，不是靠字重與大寫
- **對齊與節奏的品質**——一致的尺度讓畫面顯得「被設計過」

這個方向與長者友善**完全不衝突**，反而是同一件事：留白、層級清楚、對比足夠，對所有年齡都更好讀。

## 4. 規則

### 4.1 字級尺度（全部 ≥ 14px）

| Token | 值 | 用途 |
|---|---|---|
| `--text-display` | `clamp(28px, 3.2vw, 40px)` | 頁面主標題 |
| `--text-title` | `22px` | 區塊標題 h2 |
| `--text-subtitle` | `18px` | h3 |
| `--text-body` | `16px` | 正文（最低） |
| `--text-small` | `14px` | 輔助文字（**地板，取代所有 13px**） |
| `--text-micro` | `12px` | **僅限**品牌小字與 eyebrow，不得用於說明或狀態 |

h1 從最大 46px 降到 40px：46px 配上負字距在中文下既擠又吵，40px 已足夠建立層級。

### 4.2 字重只用三級

| 值 | 用途 |
|---|---|
| `700` | 標題與主要按鈕 |
| `600` | 次要強調、標籤 |
| `400` | 正文 |

移除 850／800／760／650。**字重不是用來分類的，是用來分層的。**

### 4.3 字距

- 中文標題 `letter-spacing: normal`（移除負值）
- eyebrow 保留寬字距（那是拉丁大寫，適用）

### 4.4 層次：邊框或陰影，不並用

| Token | 用途 |
|---|---|
| `--elevation-flat` | 卡片：**只有邊框**，無陰影 |
| `--elevation-raised` | 浮動面板、選單：柔和陰影，無邊框 |

卡片是頁面的基底，不需要浮起。真正需要「浮在內容之上」的只有選單與彈出面板。

### 4.5 間距尺度

`4 / 8 / 12 / 16 / 24 / 32 / 48`，以 token 提供。所有新樣式只能從中取值。

### 4.6 顏色

- `--navy` 維持主色
- `--gold` 提升為**唯一的強調色**，用於品牌標記與分隔線裝飾
- **金色不得用於文字**：`#d5a92e` 在白底上對比僅約 2.2:1，遠低於 4.5:1 的門檻
- eyebrow 從藍色改為 `--muted`，讓它退回輔助地位

## 5. 不會改的東西

- 48×48px 觸控區
- 320／375／412px 無水平捲動
- 200% 文字放大仍可完成核心流程
- 顏色不得作為唯一狀態指示
- 既有的元件結構與 class 名稱——**這一輪只換 token 與基礎層**，不重寫 56 個頁面

## 6. 為什麼從 token 下手

56 個頁面逐頁重畫是不可能在一輪完成的，而且會製造大量衝突（Codex 同時在開發）。

**改 token 與基礎層，56 個頁面會一起改變**，因為它們都吃同一份 `globals.css`。這是投入產出比最高的一刀，也最不容易跟別人的工作撞車。

後續的逐頁精修另立任務。

# 第二輪：Desktop 規格與蘋果設計美學

追加日期：2026-09-14（Asia/Taipei）

第一輪改的是 token 與基礎層。這一輪處理的是**版面**：桌機看起來像不像一個被認真設計過的產品。

## 7. 最高原則：Mobile 與 Desktop 是同一套產品

這條原則是這一輪所有決定的依據，也是唯一一條不接受例外的規則。

過去的實際狀況違反它最明顯的一處：**手機上方是深藍色導覽列，下方是白色分頁列**。同一個畫面，上下兩種語言。桌機側欄是深藍漸層，內容區是淺灰——導覽比它所支撐的內容還重。

所以這一輪把**側欄從深色面板改成淺色表面**，手機與桌機一致：

| | 之前 | 之後 |
|---|---|---|
| 側欄背景 | `linear-gradient(165deg, #102a41, #173d59, #0d2539)` | `var(--surface)` + 1px `var(--line)` 右邊界 |
| 側欄寬度 | 288px | 248px |
| 導覽項目 | 48px / 深底白字 | 50px / 15px / 藍色淡底 `--blue-soft` |
| 目前頁面 | 填滿的強調色方塊 | **淡色底 + 強調色文字** |

**為什麼目前頁面不再填滿顏色**：一個飽和色塊看起來像「一個該按的按鈕」，但它要說的只是「你在這裡」。淡底把它降回狀態，而不是動作。

## 8. 色票（實際值）

| Token | 值 | 說明 |
|---|---|---|
| `--ink` | `#10233d` | 主要文字 |
| `--muted` | `#62748a` | 輔助文字 |
| `--subtle-ink` | `#8795a8` | 標籤、eyebrow |
| `--line` | `#e3e9f0` | 邊界 |
| `--canvas` | `#f6f8fb` | 頁面底 |
| `--surface` | `#ffffff` | 卡片與側欄 |
| `--surface-sunken` | `#eef2f7` | 下沉區塊、hover |
| `--blue` | `#0a72e8` | **主要操作色**（填色用） |
| `--blue-ink` | `#0a5fc4` | **同一個藍色當文字用時的深色版** |
| `--blue-soft` | `rgba(10,114,232,.08)` | 目前狀態底色 |
| `--gold` | `#f4b942` | 品牌強調，**永不承載文字** |

**主要按鈕從 navy 改成 blue**：navy 是產品識別，出現在 chrome 上；用 navy 當按鈕，按鈕就在跟自己的品牌競爭。藍色是「可以按」的顏色，這是它唯一的工作。

**為什麼藍色要分成兩個 token**：`#0a72e8` 在純白上是 **4.58:1**，剛好壓線通過 AA；但它實際被畫上去的表面不是純白——
手機導覽列是 `rgba(255,255,255,.96)`（**4.28:1**），目前頁面的底是 `--blue-soft`（**4.14:1**），兩個都低於 4.5。

一個顏色當**色塊**好看，不代表它當**文字**讀得到。所以填色用 `--blue`，文字用 `--blue-ink`（`#0a5fc4`，
在同樣兩個表面上是 5.69:1 與 5.51:1）。`design-system.test.ts` 有守則擋下 `color: var(--blue)`，
避免哪天有人順手寫回去。

這個問題**現有的 E2E 對比測試抓不到**：它用 `rgba(255,255,255,.96)` 的前三個數字當背景，也就是把半透明當成純白，
所以它算出 4.58 而不是 4.28。守則寫在單元測試那一層，是因為那一層看得到 token 本身。

模式強調色保留三種（社員藍 `#0a72e8`、管理琥珀 `#a86f16`、平台紫 `#7b4ca3`），因為**一眼分辨自己在哪個模式**正是模式存在的理由。社員藍改成與系統藍同值，社員在側欄看到的顏色就是頁面上每個按鈕的顏色。

## 9. 字體

```
system-ui, -apple-system, BlinkMacSystemFont, "SF Pro Text",
"PingFang TC", "Noto Sans TC", "Microsoft JhengHei", sans-serif
```

Mac 與 iPhone 取 SF Pro + 蘋方，Windows 取系統字，Android 取 Noto。**不載入 web font**：中文字型檔動輒數 MB，載入期間的字型跳動比字型本身的差異更傷。

## 10. 間距、圓角、層次

間距尺度補上 20 與 40：`4 / 8 / 12 / 16 / 20 / 24 / 32 / 40 / 48`。原本從 16 直接跳到 24，中間沒有可用值，所以到處出現 `14px`、`18px` 這種隨手寫的數字。

| Token | 值 |
|---|---|
| `--radius-card` | `20px` |
| `--radius-control` | `14px` |
| `--elevation-card` | `0 8px 28px rgba(15,35,60,.04)` |

陰影幾乎看不見，這是刻意的：它的工作是讓卡片**離開背景一點點**，不是讓它浮起來。看得見的陰影在 2026 年看起來像 2014 年。

## 11. 首頁版面

**之前**：`max-width: 880px`。27 吋螢幕上顯示的是手機版面，左右兩片灰色。

**之後**：

- `.page-stack` 上限 **1440px**。不是整個視窗——一行文字超過約 90 個字元，眼睛會找不到下一行的開頭。桌機多出來的寬度用在**把東西並排**，不是把一欄拉長。
- **主要活動卡改成兩欄（60 / 40）**：海報在左，標題、時間、地點、按鈕在右，整張卡在第一屏內看完。用 `:has(.eventCover)` 保護——沒有海報就沒有第二欄，自動退回單欄。
- **海報比例統一為 `16 / 7`**，由 `--event-cover-aspect` 單一宣告，首頁與活動列表共用。夠寬，足以讀成 banner；夠高，合照裡的人臉不會被裁掉。
- **常用入口改成 `auto-fit` 網格**（最小 260px）。不寫死三欄：開了哪些功能決定入口有幾個，寫死三欄在第四個出現時會留一個洞。
- 主要活動標題 **26px**，狀態 pill 高度 **32px**。pill 在 24px 時，放在 26px 標題旁邊看起來像標題的註腳，而不是活動的狀態。

## 12. 移除的裝飾

| 移除 | 原因 |
|---|---|
| 主要活動卡的綠色漸層 | 它說「這是另一種東西」，但它其實是**同一種東西裡最重要的那個**。改成一般卡片 + 頂端一道金線 |
| 通知卡的琥珀色底 | 每一則例行社內訊息看起來都像出了事。改成白底 + 左側金線 |
| 祝福／財務捷徑的漸層 | 同一頁三種漸層 = 沒有一種是強調 |
| `transform: translateY(-1px)` hover | 卡片在游標下跳動，注意力跑到游標上，不是卡片上 |
| **正式版的 `ROTARY V2 · ONLINE` 標籤** | 環境標籤只在「可能認錯環境」時有價值。正式版上沒有東西可以認錯 |

最後一項的做法是讓 `environmentLabel()` 在 production 回傳空字串。先前的寫法 `{environmentLabel() && ...}` 沒有作用——那個函式永遠回傳非空字串，所以 production 仍然會顯示 `ONLINE`。

## 13. 這一輪沒有做的（需要你決定）

你提供的兩張圖是**目標稿，不是現況截圖**。圖上有幾個目前系統不存在的功能，它們不是版面問題，是新功能：

| 項目 | 需要什麼 |
|---|---|
| 搜尋框 | 一個跨社員／活動／訊息的搜尋端點 |
| 通知鈴鐺 | 訊息中心已有資料，但需要未讀計數的即時來源 |
| 待辦提醒卡 | 一份「哪些事算待辦」的定義（報名未回覆？會費未繳？） |
| 山景 hero 圖 | 一張社的代表影像，以及誰能換它 |
| 日期顯示 | 小，但要決定放在哪一層 |

「維持現有資訊架構」與「做成圖上這樣」在這幾項上是衝突的。規格裡不需要新後端的部分**這一輪全部做掉了**；上表留給你決定要不要開。

## 14. 測試守則的修正

這一輪動到兩個既有守則測試，兩個都是**把寫死的值改成真正的不變量**：

- 觸控尺寸守則原本要求 `min-height: 48px` 完全相符。48px 是**下限**不是定值——長到 50px 更好按，守則不該把它壓回去。改成比較數值。
- 海報比例守則原本寫死 `8 / 3`。真正要守的是「只有一個比例，而且兩個地方都讀同一個 token」，不是那個數字本身。改成檢查不變量。

兩個修改後的守則都**實際驗證過會在違反時失敗**（把值改壞、確認紅、再改回來），不是只讓它變綠。
