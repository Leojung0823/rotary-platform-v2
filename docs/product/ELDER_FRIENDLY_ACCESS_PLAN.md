# 我是扶輪人：長輩友善入口企劃

更新日期：2026-11-03｜狀態：階段 1 開發中；其他階段待決定

## 一頁摘要

**問題：** 社員常從 LINE 點活動、議題或社團訊息，但在 LINE 內建瀏覽器開啟後，可能遇到重複登入、登入狀態不同或功能不好操作。長輩不應先學會安裝另一個 App，才能使用社務系統。

**目標：** 先讓社員從 LINE 一按即可前往適合使用的瀏覽器，以大按鈕找到社團的重要事項；需要時由志工面對面協助把網站放到手機桌面。

| 階段 | 交付 | 需誰決定 |
| --- | --- | --- |
| 1. 開啟連結 | 系統建立的 LINE 連結附加外開參數；LINE 內進入網站時嘗試補參數，保留手動外開教學 | 管理員決定何時發布，社員回報手機體驗。 |
| 2. LINE 圖文選單 | 每社 OA 的大按鈕與連結，例如近期活動、我的報名、社內議題 | 各社決定按鈕與圖片；OA 管理員負責後台設定。 |
| 3. LIFF 評估 | 比較登入、使用限制與工作量，提出是否實作的建議 | 產品負責人決定是否投入；此階段不開發 LIFF。 |
| 4. 現場協助 | 例會 QR 卡、簡短教學、志工協助社員 | 社長或秘書決定時間，找志工及安排印製。 |

## 階段 1：LINE 連結與外部瀏覽器

- 活動通知、邀請、圖文選單、生日與待辦提醒等由系統產生的網站連結使用 `openExternalBrowser=1`。保留原有網址、查詢參數與目的地；不修改社員自行輸入的文字或第三方連結。尚無專用的議題 LINE 分享產生器，未來建立時應使用共用連結函式。
- 當一般頁面從 LINE 內建瀏覽器進站且未帶參數時，伺服器嘗試在原網址加上參數後轉址；已有參數不再轉址。登入 callback、API、靜態資源、非頁面請求及 LIFF 請求不做這項處理。
- LINE 的[官方文件](https://developers.line.biz/en/docs/messaging-api/using-line-url-scheme/)說明參數可用於從 LINE 開啟一般網址，但沒有確認伺服器轉址後一定能切換瀏覽器；**以 LINE 訊息原始連結帶參數為主要方式，轉址是輔助**。若仍留在 LINE，沿用現有「用瀏覽器開啟」教學。LIFF 不適用此參數。
- 登入與社團權限維持現有機制，不更動 LINE channel 或 callback 設定。實機驗證作為後續觀察，不列為本次交付的發布阻擋條件。

## 階段 2：社團 LINE 圖文選單

規劃每社 OA 放置容易點擊的大按鈕，可從「近期活動／我的報名／社內議題／我的資料」選擇，實際入口依現有頁面能力確認。圖文選單與網站共用同一社團資料與社員權限。

交付包含按鈕文案、連結、圖片規格與測試清單；OA 管理員於對應社團後台設定。既有選單不會因程式改動自動更新，需另安排外部設定及確認。現行範圍維持 PANCHIAO-ELITE，HAPPY 不使用。

## 階段 3：評估 LIFF，不實作

| 項目 | 外部瀏覽器 | LIFF 候選方案 |
| --- | --- | --- |
| 登入 | 走既有 LINE Login；視瀏覽器狀態可能需登入 | 可使用 LINE 的 LIFF 身分功能，但仍須設計與現有平台帳號的安全連結，不等於自動取得社員權限。 |
| Session | Safari／Chrome 各自保存，與 LINE 內可能不同 | LIFF 瀏覽器與 LINE 內建瀏覽器不同；Session、過期與回跳需實測。 |
| 相機／QR | 使用手機瀏覽器既有權限與簽到流程 | 可評估 LIFF 掃碼或既有網頁相機；iOS／Android 支援及權限需逐項測試。 |
| 分享連結 | 一般網址加外開參數 | LIFF URL 的參數與開啟方式不同；要確認深層連結、未登入回跳及分享。 |
| 工作量 | 以現有網站小幅改善為主 | 初步估計需額外 2–4 週做技術驗證、帳號連結及裝置測試；未盤點前為粗估。 |

LIFF 的優點是可與 LINE 使用情境整合；代價是多一套平台行為及維護，且不能只靠 LINE 身分取代平台的社籍與授權。正式評估時產出測試報告、成本與建議，再由產品負責人決定。

## 階段 4：例會現場協助

1. 印製含可信網站網址及 QR Code 的小卡，附「遇到問題找現場志工」。QR 指向公開入口，不包含社員邀請碼或個資。
2. 志工協助 iPhone 社員以 Safari 開啟；請社員自己完成登入。Safari 的分享按鈕位置依版本可能不同，可從選單找到「分享」，再選「加入主畫面」並確認。
3. 協助 Android 社員以瀏覽器選單使用「安裝應用程式／加到主畫面」。
4. 確認社員能自己再次打開、找到活動；不代記密碼、不要求出示驗證碼。

## 成功指標與資料取得

- **登入成功比例：** 以不含個資的聚合事件統計，計算從 LINE 入口開始後，在同一匿名流程中完成登入的次數／開始登入的次數；先定義時間窗及排除測試流量，再建立基準。尚無量測，不假設現有數字。
- **圖文選單使用：** 各按鈕點擊及到達目標頁次數；若 OA 後台僅提供聚合值，先以聚合數回報，不假稱可識別不重複社員。
- **社員問題：** 每週登記重複登入、找不到入口、相機／定位等問題數，依回報類型追蹤趨勢。
- 上述追蹤需先設計同意、保留期限、去識別及防重複方案，不收集完整網址、邀請碼、登入憑證或議題內容；本次不新增追蹤。

## 建議的手機確認項目

- iPhone 與 Android 各從 LINE 點活動、帶既有查詢參數的議題連結、邀請連結與圖文選單。
- 確認是否在外部瀏覽器開啟、登入後回到原頁、已登入與未登入的結果；若留在 LINE，確認手動外開教學可找到。
- 再檢查 LINE Login callback、LIFF 入口、社團切換、無權限頁、相機與定位提示。
- 記錄手機、系統／LINE 版本、網址類型與結果；此清單供參考，不作為本次上線的阻擋條件。
