## Structural findings

1. All UUID identities are generated in DB except bigint event tables; every table has a PK.
2. `login_history.device_id` and `user_devices.session_id` are not declared FKs, so device/session ledger integrity is application-managed.
3. `line_push_logs` has no secondary index despite OA/time admin reads; `notification_settings`, `privacy_settings`, catalog/join tables rely on PK access.
4. Legacy mutable membership/account/role/invitation tables generally have `updated_at`; append logs use only created/received timestamps. Membership status lacks immutable history.
5. The 0-policy design blocks all direct client table access, but service routes can bypass it; direct access inventory is in `V12_FRONTEND_DEPENDENCIES.md:45-58`.
6. V1.2 target/data handling for every row is in `V12_LEGACY_TABLE_MAPPING.md:7-33`; no table may be silently dropped because a direct target is absent.
